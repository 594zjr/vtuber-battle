# 专家 AI：前瞻策略与验证

T-35，2026-10-15；基线 `af59b9e`，包含 T-12 困难 AI、T-33 普通 AI 权重和 T-34 完整对战拷贝；提交前同步至 `9cbef7a`，保留 T-29/T-37 的联网会话、战报导出、T-39 的自动组队入口和 T-38 的天梯工具（不改原对战结算或 AI）。仅新增专家策略，原有简单、普通和困难策略保持不变。

## 决策

`Ai.Choose(battle, side, AiLevel.Expert)` 在选择行动阶段使用；`Ai.ChooseReplacement(battle, side, AiLevel.Expert)` 在该方需要补位时使用。空对战、非法方位或不匹配的阶段会抛出参数或阶段异常。普通权重重载在 Expert 下继续走专家策略，不采用普通难度权重。

1. 通过 `Battle.Clone()` 建立独立规划副本，只在副本中清空历史日志和回放事件，避免每个分支反复复制整场历史；内容定义仍只读共享。
2. 枚举全部可用技能、硬撑或受控跳过，并纳入 `LegalFor` 允许的换人。受控或 PP 耗尽时仍可换人；锁麦限制由引擎决定。不会把跳过和硬撑列成两个等价候选。
3. 在同一组 3 个副本随机流起点上预测困难 AI 的行动，再为每个本方候选调用真正的 `ResolveTurn` 和 `Replace`。3 个起点分别推进副本 RNG 0、11、22 次；预测和模拟不消耗真实对战的 RNG。
4. 评价双方存活人数、人气比例、可用攻击对应的能力等级、控制/持续状态、直播间效果及 PP 枯竭。接近 120 回合时逐渐降低存活人数权重，以符合按人气比例决胜的规则；胜负终局高于普通局面分。
5. 第一层前 3 名及边界同分者再用双方困难策略推演一回合；合并第一层 30% 和第二层 70% 的评分。最高分相同才调用一次真实 `battle.Random()` 抽签。搜索深度和采样次数固定，不按墙钟时间截断。

补位逐个尝试所有仍在播的后排，调用真实 `Replace`，补齐另一方尚未完成的补位，再推演一回合。规划过程中的补位使用困难策略，避免递归调用专家策略造成搜索膨胀。所有模拟均局限于独立副本，真实队伍、PP、状态、日志、回放及累计统计不变。

这是有限采样、有限深度的启发式策略，不是遍历所有未来的最优解；对手仅采用困难 AI 主预测。自定义高层数印记等特殊内容的估值仍可能偏离实际价值。

## 复现

```powershell
dotnet test Engine.Tests
pwsh -File Tools/Sim/check-expert.ps1 -Mode acceptance -Games 200
pwsh -File Tools/Sim/check-expert.ps1 -Mode random -Games 200
dotnet run --project Tools/Sim -- --pack original --level expert --games 100 --seed 1
dotnet run --project Tools/Cli -- --pack original --level expert --auto --ban --lead --hash
```

`check-expert.ps1` 不改内容或权重，临时项目与输出在 `Tools/Sim/obj/t35-benchmark` 下，运行结束恢复原 TEMP/TMP。无新增依赖。默认 Debug 构建，以普通与验收测试相同的 .NET 8 环境运行；最终输出 JSON，进度写入标准错误。

- `acceptance`：与原验收测试一致，12 人名单逐局轮转、前后各 6 人，seed 为 1000～1199，专家在双方各 100 局。
- `paired`：每两局复用同一阵容和种子，交换专家所在侧，排除阵容与方位绑定。
- `random`：用 `Battle.Random()` 打乱阵容，seed 从 5000 起；每两局复用相同阵容和种子，交换专家所在侧。paired/random 的局数必须为正偶数。

计时只覆盖专家的行动和补位选择，包含中后期长日志、首次冷启动及可能的 GC；不包含困难 AI 的实际行动选择或真实回合结算。每局必须到达 Over，保护循环耗尽时抛错，不会把未完成的局数计入胜率。均值要求为不超过 50 ms，不是每次调用都必须低于 50 ms。

## 实测

未修改原验收的任何断言。修正重复跳过候选后的 200 局验收分队：178 胜、22 负、0 平，胜率 **89%**；专家在 0 方为 87/100 胜，在 1 方为 91/100 胜，平均 40.4 回合。

| 范围 | 调用次数 | 平均耗时 |
|---|---:|---:|
| 专家行动 | 8080 | 19.104961 ms |
| 专家补位 | 208 | 15.060841 ms |
| 全部专家决策 | 8288 | 19.003467 ms |

该轮最慢一次 73.2473 ms，总运行 163.241268 秒。全部决策平均低于 50 ms，含单次高于 50 ms 的调用；这些数值是本机当次实测，性能会受运行环境影响。

冻结策略后另跑随机阵容、同阵容与种子交换专家方位的 100 对共 200 局（seed=5000～5099），没有再调整参数：190 胜、10 负、0 平，胜率 **95%**；专家在 0 方 92/100 胜，在 1 方 98/100 胜，平均 38.83 回合。

| 范围 | 调用次数 | 平均耗时 |
|---|---:|---:|
| 专家行动 | 7766 | 19.810142 ms |
| 专家补位 | 132 | 17.166079 ms |
| 全部专家决策 | 7898 | 19.765952 ms |

随机阵容轮最慢一次 72.0942 ms，总运行 161.967810 秒。两组结果都针对原创包、固定种子和困难 AI 对手，不能据此保证任意自定义内容包或真人策略下的胜率。

边界测试覆盖真实对战完整公开状态/统计/定义不变、同种子决定一致、唯一候选不推进真实 RNG、受控与锁麦组合、PP 耗尽、团魂零 PP、双方同时待补位、唯一补位及等价技能的可复现随机平分。CLI 和 Sim 均支持 easy/normal/hard/expert，自动行动与补位使用同一级别；未指定难度保持普通。`--tune` 专门调普通权重，与显式 `--level` 同用时明确报错。
