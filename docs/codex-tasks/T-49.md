# T-49 模糊测试与确定性回归

依赖：无（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。

## 目标
用大量随机对局找出崩溃和规则漏洞，并锁住“同样输入同样结果”，防止以后的改动悄悄改变对战结果。

## 要做的
1. 新测试 `Engine.Tests/FuzzTests.cs`：对每个内容包，2000 局（测试里用 300 局，另提供环境变量 `SD_FUZZ=2000` 时跑满）：随机组队（合法）、随机开启禁用/首发/修饰器（若已合并）、每回合双方随机选**任意**行动（包括非法的技能号、换到已下播的人、被控制时出招），检查不变量：不抛异常；人气在 0～最大值；PP 在 0～上限；能力等级在上下限内；同时最多 1 个控制类状态；阶段转换合法；`TurnCap` 内结束；结束后用记录重放得到相同 `StateHash`。失败时把种子和记录 JSON 写进断言信息。
2. 新测试 `Engine.Tests/GoldenTests.cs` + 数据文件夹 `Engine.Tests/Golden/`：每个内容包 10 个固定种子、普通难度对普通难度，整局日志存成文本；测试逐字比较。环境变量 `SD_UPDATE_GOLDEN=1` 时改为重写这些文件。README 写明：**有意改规则时**才更新 golden，并在 PR 描述里说明。
3. 找到的 bug 直接修（每个 bug 一个小提交，提交信息写清楚），并在 PR 里列出来。
4. CI（`.github/workflows/test.yml`）不需要改。

## 验收
新测试全部通过；PR 里列出发现并修复的问题（没有发现也写明）。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
