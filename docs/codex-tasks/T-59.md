# T-59 画面基础框架：UI Toolkit、中文字体、新输入系统、界面路由（需要本机有 Unity）

依赖：T-08（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。本游戏只做对战（玩家对玩家、玩家对电脑）。

## 目标
给后面可以**并行**做的画面任务（T-66～T-71）打好地基：每个界面一个文件夹，互不冲突；顺带消除 T-08 暂留的「旧输入系统弃用」警告。

## 要做的
1. **输入**：`Packages/manifest.json` 加 `com.unity.inputsystem`（用 Unity 6.6 自带推荐的版本）；Player Settings 的 Active Input Handling 改为 Input System Package (New)。旧的 IMGUI 对战画面在 T-67 完成前还要能用；如果改成新输入后旧画面点不动，就暂时设为 Both，在 PR 里写清楚，T-67 删除旧画面时再改回 New。合并时 Console 不能再有输入系统弃用警告（设为 Both 时如果仍有这条警告，在 PR 的「需要决定」里写明）。
2. **字体**：从 Google 官方仓库 notofonts/noto-cjk 下载 Noto Sans SC（SIL OFL 1.1）的 Regular 和 Bold 两个字重，放到 `Assets/StreamDuel/Fonts/`，同目录放 `OFL.txt`；仓库根目录新建 `THIRD_PARTY.md` 记录字体名、来源网址、许可。不要用系统自带字体文件。
3. **UI Toolkit 运行时**：`Assets/StreamDuel/UI/PanelSettings.asset`（参考分辨率 1920×1080，按宽高匹配缩放）、`Assets/StreamDuel/UI/Theme.uss`（颜色变量：背景、面板、强调色、各赛道颜色取自 `StreamDuelRules.json` 的 TypeDef.Color，在代码里设置；字号三档）。
4. **界面路由**：新文件 `Game/UI/ScreenRouter.cs`（一个 `UIDocument`，`Show(string screenId, object args)`，屏幕之间只通过参数对象传数据）和 `Game/UI/IScreen.cs`（`string Id`、`VisualElement Build(ScreenRouter r, object args)`、`void Tick(float dt)`、`void Dispose()`）。每个界面放在 `Game/Screens/<名字>/` 文件夹，T-59 只放占位：`Team`、`Battle`、`Result`、`Replay`、`Settings`、`Online`，每个占位界面显示标题和「返回」按钮。
5. **对战舞台接口**（给 T-67、T-68、T-69 并行用，放 `Game/Screens/Battle/BattleStage.cs` 和 `Game/Anim/Interfaces.cs`）：
   - `BattleStage`：一个 `VisualElement`，里面有双方上场位 `fighter-0`、`fighter-1`（各含 `portrait`、`hp-bar`、`status-row` 子元素）、特效层 `fx-layer`、跳字层 `float-layer`、场地横幅 `field-banner`。元素名写成常量类 `StageNames`。
   - `interface IBattleAnimator { void Play(IReadOnlyList<AnimCue> cues); bool IsPlaying { get; } void SkipToEnd(); }`、`interface IFxPlayer { void Play(string fxId, VisualElement from, VisualElement to, float duration); }`、`interface IStatusIconProvider { VisualElement Make(string iconId, string label); }`、`interface IPortraitProvider { Texture2D Get(ContentDb db, string streamerId); }`。
   - 都给一个什么都不做或最简单的默认实现（`NullAnimator` 直接结束、`NullFx`、文字图标、纯色头像），保证没有后续任务也能跑。`AnimCue` 来自 T-60；T-60 还没合并时，在 `Game/Anim/` 先放一个同名占位类并在 PR 里注明，T-60 合并后由审查员删掉占位。
6. **入口**：`GameBoot` 改为创建 `ScreenRouter`，默认进入旧的 IMGUI 对战画面（保持现在的可玩状态），主菜单（新文件 `Game/Screens/Menu/`）有按钮进入每个占位界面和「旧版对战」。

## 不要做
- 不做任何具体界面的内容（那是 T-66～T-71）。
- 不删除旧的 `BattleScreen.cs`（T-67 删）。

## Unity 任务的共同规则
- **本机没有安装 Unity 就不要领这个任务**（跳过它领下一个）。不要自己安装 Unity。
- 在自己的工作树 `D:\vtuber-battle-wt\T-xx` 里用 Unity Hub 打开 `UnityProject/`（第一次导入较慢，正常）；做完关闭这个 Unity 窗口，省内存。不要打开别的工作树或 `D:\vtuber-battle` 主目录的工程。
- 只改本任务列出的文件夹；需要改共享文件（`GameBoot.cs`、`ProjectSettings/`、`Packages/manifest.json`、T-59 的接口文件）时改动尽量小，并在 PR 描述里逐条说明。
- 画面层只调用 Core 的公开接口（`BattleViewModel`、`Battle.Events`、`BattleTimeline` 等），**不在画面里算任何规则**。
- **素材禁令**：不使用任何官方立绘、截图、Live2D、3D 模型、音频、Logo；不使用来源不明的图片或字体。头像、特效、图标全部用代码生成的占位（色块、几何图形、名字首字），或按内容包路径加载用户以后自己放进去的图片；仓库里不提交任何头像图片。
- 立绘和动画资源一律按内容包路径加载、可以替换（路径约定见 T-61）；以后换成手绘图或 Live2D 只换资源和一个实现类，不改对战界面代码。
- 验收截图贴在 PR 描述或评论里，不要提交进仓库。PR 里写 Unity 版本。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过。
2. 本机 Unity 打开工程 Console **无红色报错、无黄色警告**（T-59 合并后不再有任何例外）；按 Play 能完整打完一局；1280×720 和 1920×1080 下不重叠、不截字。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
