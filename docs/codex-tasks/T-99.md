# T-99 回合上限的判定细则

依赖：T-23（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。本游戏只做对战（玩家对玩家、玩家对电脑）。

## 目标
现在打到回合上限（120 回合）的结果规则不够细，容易出现「拖平」。把判定规则写清楚并实现。

## 要做的
1. 到达 `Battle.TurnCap` 时依次比较：①剩余未倒下人数多者胜；②剩余人气占最大人气百分比总和高者胜；③本局造成的总伤害高者胜；④仍相同为平局。结果和原因写日志（例如「回合上限：双方剩余人数相同，按剩余人气判定」）。
2. 规则写进 `docs/design.md`；`BattleSummary` 增加 `EndReason`（击倒全灭 / 回合上限 / 投降 / 和局 / 断线）。
3. `TurnCap` 可以由规则修饰器或赛制覆盖（如果 T-46/T-54 已合并，加一个 `turn_cap_60` 修饰器）。
4. 检查现有测试里依赖旧上限行为的地方；如果旧测试断言与新规则冲突，在 PR 的「需要决定」里列出，不要改旧断言。

## 验收
自带测试 `Engine.Tests/T99_TurnCapTests.cs`：构造到达上限的局面（例如双方都只用状态技能），四级判定各至少一个用例；`EndReason` 正确；录像重放一致。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
