# T-13 内容包检查工具与名单文档

依赖：无（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。

## 目标
改内容包（特别是同人包）时一条命令就能查出问题，并自动生成可读的名单文档。

## 要做的
1. 新命令行工程 `Tools/PackCheck/PackCheck.csproj`（net8.0，引用 `Engine/StreamDuel.Core.csproj`），加进解决方案或在 README 写用法：`dotnet run --project Tools/PackCheck -- [--pack <id>] [--write-docs]`。
2. 检查（每条问题打印 `[错误]` 或 `[提醒]` 和位置，有错误时退出码 1）：
   - `ContentDb.Validate()` 全部规则；
   - 每位主播有 `blurb`，长度 ≤ 40 字；同人包（id 以 `fan_` 开头）必须有 `notice` 且含“非官方同人作品”；
   - 同人包里出现可能影射真人的词时提醒：从 `Tools/PackCheck/sensitive_words.txt` 读取（先写入：中之人、炎上、黑历史、塌房、退圈、毕业、绯闻、黑粉、怒删），检查主播名以外的所有显示文字，包括改名后的技能/状态/效果名和人设名；
   - 没有被任何主播用到的技能列为 `[提醒]`。
3. `--write-docs`：为每个内容包生成 `docs/roster/<packId>.md`（主播、所属、赛道、人设名与说明、5 个技能及每个效果的判定时机和能否消除——文字用 `Describe.cs`）。生成后提交这些文档。
4. CI（若 T-07 已合并）里加一步运行 PackCheck。

## 验收
运行无错误；故意把某位主播的技能 id 改错，能报出具体位置（验证后改回）。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
