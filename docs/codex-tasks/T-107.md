# T-107 问题报告码（一键复现对战）

依赖：T-48（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。本游戏只做对战（玩家对玩家、玩家对电脑）。

## 目标
测试的人发现对战里有奇怪的结果时，可以生成一段「问题报告码」发出来，开发者粘贴后能原样复现。

## 要做的
1. 新文件 `Core/BugReport.cs`：`BugReport.Create(Battle b, string note)` 生成文本码（前缀 `SDBUG1-`，复用 T-48 分享码的压缩和校验方式），包含：录像、内容包 id 和 `ContentHash`、引擎版本、录像版本、最后 30 行日志的哈希、玩家备注（经 T-97 文字过滤，如已合并）。
2. `BugReport.Parse(string code)` 和 `BugReport.Reproduce(ContentDb db, BugReport r)`：重放并比对最终 `StateHash`；内容包或版本不同时给出中文说明（仍尽力重放）。
3. 不包含任何账号、设备、网络地址信息。
4. `Tools/Cli` 加 `--bug-report`（对战结束或中途输入 `/bug` 生成）和 `--reproduce <码>`。

## 验收
自带测试 `Engine.Tests/T107_BugReportTests.cs`：生成再解析后复现的哈希一致；码被篡改一个字符时校验失败给中文提示；内容哈希不同给出说明；长度在 4000 字符以内（一局 120 回合的录像）。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
