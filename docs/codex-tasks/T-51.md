# T-51 自制内容包教程与示例包

依赖：T-19、T-27（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。

## 目标
开源之后，别人照着一篇教程就能做出自己的内容包。

## 要做的
1. 新文档 `docs/modding.md`（中文）：内容包放哪里（Unity 的 `persistentDataPath/packs/`、命令行的 `--pack-dir`）、JSON 的每个字段、怎么写技能效果（每个效果码一个最小例子，写清判定时机和能否被消除）、怎么写人设、包内自带技能/人设/效果/状态、双赛道、赛季、闯关（若已合并）、怎么用 `PackCheck` 检查、怎么用 `Sim` 测平衡。**引用示例文件的路径时写 `docs/examples/`。**
2. 新文件夹 `docs/examples/`，放一个完整可用的示例包 `example_pack.json`：6 位原创虚构主播（名字一看就是示例，例如“示例主播·甲”），至少 3 个以 `ex_` 开头的包内技能、1 个包内人设、1 个包内效果。
3. 文档里明确写出同人包的底线（链接 `FANWORK.md`），以及“不得放入官方素材”。
4. README 的“自制内容包”一节链接到 `docs/modding.md`。

## 验收测试
把 `Engine.Tests/Pending/T51_ExamplePackTests.cs` 移到 `Engine.Tests/`，让它通过。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
