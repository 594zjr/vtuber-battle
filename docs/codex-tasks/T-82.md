# T-82 内容包文本检查工具（长度、禁用词、一致性）

依赖：T-27（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。本游戏只做对战（玩家对玩家、玩家对电脑）。

## 目标
自动检查所有内容包的文字：界面放得下、没有违禁内容、写法一致。以后新增内容包都先过这一关。

## 要做的
1. 新文件 `Core/TextLint.cs`：`public static List<LintIssue> Check(ContentDb db)`；`LintIssue { string Level /* error|warn */, Where, Id, Message; }`。
2. 检查项（数值写成常量，写进 `docs/design.md` 内容包一节）：
   - 长度：主播名 ≤ 10 字、技能名 ≤ 6 字、人设名 ≤ 8 字、状态/直播间效果名 ≤ 6 字、简介 ≤ 40 字（超了 warn，超 1.5 倍 error）。
   - 禁用词（error）：新文件 `Resources/Lint/banned.txt`，一行一个，至少包括赛尔号相关的游戏名、公司名，以及「中之人」「前世」「转生」「本人」「真名」「黑历史」「炎上」「毕业」之类涉及真人或负面话题的词；同人包另外不得出现「官方」「授权」字样（声明字段 `notice` 除外）。
   - 一致性（warn）：中文里混用半角标点（，。：；！？）；数字和单位之间多余空格；同一技能在说明里的名字和 `name` 不一致。
   - 空文本、只有空白（error）。
3. `Tools/PackCheck` 调用它并输出；有 error 时退出码非 0。CI（T-07 的 GitHub Actions）里加一步跑 PackCheck。
4. 现有内容包如果查出 error，**只改文字**修掉（不改数值和结构），每处改动列在 PR 里；warn 可以留着但要在 PR 里列出数量。

## 验收
自带测试 `Engine.Tests/T82_TextLintTests.cs`：所有内置包没有 error；构造一个含禁用词、超长名字、空简介的包，分别查出对应问题；`notice` 字段里的「官方」不报错。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过（包括原有的所有测试，不得修改原有测试的断言）。
2. 只改本任务列出的文件；需要改别的文件时在 PR 描述里说明原因。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
