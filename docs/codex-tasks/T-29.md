# T-29 联网对战：同步会话（不含真实网络）

依赖：无（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。

## 目标
两台电脑各跑一份引擎，只交换玩家的行动，每回合比对状态哈希。这个任务只做协议和状态机，用内存里的“假网络”测试；真实 TCP 在 T-31。联网相关代码放 `Core/Net/`，命名空间仍是 `StreamDuel.Core`；只用 .NET Standard 2.1（Unity 也要能编译），不引入 NuGet 包。

## 要做的
1. `public interface INetTransport { void Send(string msg); bool TryReceive(out string msg); }`；`public static class LoopbackPair { public static void Create(out INetTransport a, out INetTransport b); }`（两端互相投递，先进先出，不丢不重）。
2. `public enum NetState { Handshake, Choose, Replace, Waiting, Over, Desync, Error }`。
3. `public sealed class NetSession`：
   - 构造 `NetSession(ContentDb db, INetTransport t, bool host, IList<string> myTeam, string myName, uint? seed)`；主机 `MySide = 0`，客机 `MySide = 1`；种子由主机决定（null 时由主机用 `Environment.TickCount` 生成一次，**只用于这个种子**）。
   - 属性 `State`、`Battle`（握手完成前为 null）、`MySide`、`HasSubmitted`（本阶段本方是否已提交）、`Error`（中文原因）。
   - `Poll()`：处理收到的所有消息、推进状态；`Submit(BattleAction)`（Choose 阶段）；`SubmitReplace(int to)`（本方需要补位时）。非法调用抛 `InvalidOperationException`。
4. 协议：每条消息是一行**紧凑 JSON（无多余空格）**，必有 `"type"`：
   - `hello`：协议版本、`packId`、主机的 `seed`、名字、队伍 id 列表。双方都发；对方 `packId` 不同、协议版本不同、或队伍不合法（`TeamCheck.Validate(db, null, team)` 非空）→ 本端 `Error`（写明原因）并给对方发 `error`。
   - `action`：`{"type":"action","turn":N,"action":"S2"}`，用 `BattleAction.ToWire()`。
   - `replace`：`{"type":"replace","turn":N,"to":3}`。
   - `hash`：每次本地 `ResolveTurn`/`Replace` 之后发 `{"type":"hash","turn":N,"hash":"<16 位小写十六进制>"}`；收到对方哈希后按**字符串**比较，不一致 → `Desync`，`Error` 写出回合和双方哈希。
   - `error`：对方报错，本端也进入 `Error`。
5. 对战双方队伍顺序固定为 `[主机队伍, 客机队伍]`，名字同理。两端都收到对方行动后才 `ResolveTurn`；补位同理（只有需要补位的一方提交，另一方等待）。
6. `docs/design.md` “以后”一节改写为“联网对战（进行中）”，写清协议。
