# T-12 电脑难度：困难

依赖：T-05、T-06（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。

## 目标
给老玩家一个更强的电脑：会算谁先手、能不能一击带走、换人后会不会被打死。

## 要做的
1. `Core/Ai.cs`：`AiLevel` 加 `Hard`。新逻辑放新文件 `Core/Ai.Hard.cs`（`partial` 或静态辅助类均可）。
2. 困难的思路（用 T-05 的 `PreviewDamage` / `PreviewOrder`，**不得消耗 Battle 的随机数**，不得修改对战状态）：
   - 双方各自的最佳伤害技能下，谁先手、几下能击倒对方（按最小伤害保守估计）。
   - 我先手且能一击击倒 → 用它；对手先手且能一击击倒我 → 如果有队友能扛住这一下并且对位更好，换人；否则用自己最好的选择。
   - 其余情况在普通难度的估值上，对“能让对手下回合打不死我”的强化/护盾/控制加分。
   - 补位：选“对手当前场上主播打我最疼的一招”下剩余人气比例最高、且能对它造成最大伤害的队友。
3. 只在做决定时用 `b.Random()` 打破平局。

## 验收测试（你自己写）
新文件 `Engine.Tests/T12_HardAiTests.cs`：
- 原创包，阵容按种子轮换（参考 `T06_AiLevelTests.cs` 的写法），困难对普通 300 局，困难胜率 ≥ 58%（交换先后两边各一半）。
- 同一种子、同样输入，困难的选择完全一致（重复两次比较整局日志）。
- 调用困难 AI 前后，`Battle` 的随机数状态不变（先记一次 `b.Random()` 的序列，再在新对战里插入 AI 调用后对比；或用你认为更直接的办法）。
在 PR 里写出你实测的胜率。
