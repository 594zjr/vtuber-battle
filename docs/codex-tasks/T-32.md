## 目标
双方同时出招，但网络上总有一方先收到对方的行动。用“先承诺、后公开”防止后收到的一方根据对手行动改选择。联网相关代码放 `Core/Net/`，命名空间仍是 `StreamDuel.Core`；只用 .NET Standard 2.1（Unity 也要能编译），不引入 NuGet 包。

## 要做的
1. 把 T-29 的 `action`/`replace` 换成两步：
   - `commit`：`{"type":"commit","turn":N,"kind":"action|replace","digest":"<SHA-256 十六进制>"}`，digest = SHA-256(`行动编码 + "|" + 随机串`)。
   - 双方都收到对方 `commit` 之后，才发 `reveal`：`{"type":"reveal","turn":N,"kind":"...","action":"S2","nonce":"<随机串>"}`。
   - 收到 `reveal` 后重算 digest，与之前的 `commit` 不符 → `Error`，信息含“承诺”二字（例如“对手公开的行动与承诺不符”）。
2. 随机串用 `System.Security.Cryptography.RandomNumberGenerator` 生成 16 字节（十六进制）。这是唯一允许不经过 `Battle.Rng` 的随机数，它不影响对战结果，在代码注释里写明原因。
3. 只有一方需要补位时，另一方不需要 commit。
4. 协议版本号加 1；`docs/design.md` 联网一节更新。
