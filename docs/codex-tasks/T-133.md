# T-133 本地赛事界面（需要 Unity）（需要本机有 Unity）

依赖：T-59、T-115、T-110（依赖的任务在 docs/TASKS.md 里标 ✅ 之后才能领）

先读仓库根目录的 AGENTS.md 和 docs/design.md，严格遵守其中的规则和禁止事项（Core 不得引用 UnityEngine、只用 C# 9、随机数只能来自 Battle 自带的 Rng、不得提交官方素材、不得出现赛尔号文本、不得修改 LICENSE、Packs/LICENSE.md、FANWORK.md 和 README 里的同人声明）。本游戏只做对战（玩家对玩家、玩家对电脑）。

## 目标
本地赛事（循环赛、瑞士轮、单败、双败）现在只能在命令行用。做一个画面：创建赛事、看对阵表、开打或录入结果、看战报。

## 要做的
1. 新界面放在 `Game/Screens/Tournament/`，从主菜单进入。
2. 创建页：选赛制、人数（2～16）、每位选手是玩家还是电脑（电脑选难度）、队伍（复用组队界面 T-66 的队伍预设选择，不重写组队）、种子方式（报名顺序、随机、按排位分）。
3. 对阵页：循环赛/瑞士轮显示积分表和本轮对阵；淘汰赛画对阵树（胜者组、败者组、总决赛，用 UI Toolkit 元素画线即可）。点一场：双方都是电脑时可「自动打完」；有玩家时进入对战界面（T-67 合并前进旧对战画面）。
4. 结束页：显示 `TournamentReport`（T-110）的文字，提供「复制战报」。
5. 赛事存档与续赛调用 Core 现有接口；画面里不算任何赛事规则。

## 不要做
- 不改 Core 的赛事规则；需要的查询接口不够时在 PR 里说明，最小改动。

## Unity 任务的共同规则
- **本机没有安装 Unity 就不要领这个任务**（跳过它领下一个）。不要自己安装 Unity。
- 在自己的工作树 `D:\vtuber-battle-wt\T-xx` 里用 Unity Hub 打开 `UnityProject/`（第一次导入较慢，正常）；做完关闭这个 Unity 窗口，省内存。不要打开别的工作树或 `D:\vtuber-battle` 主目录的工程。
- 只改本任务列出的文件夹；需要改共享文件（`GameBoot.cs`、`ProjectSettings/`、`Packages/manifest.json`、T-59 的接口文件）时改动尽量小，并在 PR 描述里逐条说明。
- 画面层只调用 Core 的公开接口（`BattleViewModel`、`Battle.Events`、`BattleTimeline` 等），**不在画面里算任何规则**。
- **素材禁令**：不使用任何官方立绘、截图、Live2D、3D 模型、音频、Logo；不使用来源不明的图片或字体。头像、特效、图标全部用代码生成的占位（色块、几何图形、名字首字），或按内容包路径加载用户以后自己放进去的图片；仓库里不提交任何头像图片。
- 立绘和动画资源一律按内容包路径加载、可以替换（路径约定见 T-61）；以后换成手绘图或 Live2D 只换资源和一个实现类，不改对战界面代码。
- 验收截图贴在 PR 描述或评论里，不要提交进仓库。PR 里写 Unity 版本。

完成标准：
1. 运行 `dotnet test Engine.Tests`，全部通过。
2. 本机 Unity 打开工程 Console **无红色报错、无黄色警告**（T-67 合并前允许只剩「旧输入系统弃用」这一条，见决定记录）；按 Play 能完整打完一局；1280×720 和 1920×1080 下不重叠、不截字。
3. 按 `.github/pull_request_template.md` 开 PR，标题以任务编号开头。
