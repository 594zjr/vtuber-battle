# 引擎性能基准

在仓库根目录使用 .NET 8 SDK 运行：

```powershell
dotnet run -c Release --project Tools/Bench -- --quick
dotnet run -c Release --project Tools/Bench
```

第一条用较小的固定样本集检查性能，第二条增加采样量。工具只接受 `--quick`、`--help` / `-h`；Debug 构建会报错。终端打印结果表，并将环境、样本数、工作负载和指标写入当前工作目录的 `bench_out/bench.json`，再次运行会覆盖该报告。

## 测量口径

- 使用固定种子和固定阵容，各指标先预热，再用 `Stopwatch` 计时。时间不参与规则或 AI 选择。
- 基准工程关闭分层 JIT 编译，减少采样期间从初级代码切换到优化代码造成的模式差异；不改变引擎或其他客户端的运行配置。JSON 记录该配置，比较结果时保持一致。
- 普通对普通吞吐包含新建对战、双方普通 AI 决策、补位和完整结算直到结束，保留正常日志与回放。它包含构造对战时的内容指纹计算，不含载入内容库及输出报告。
- 四档 AI 在相同的开局、中盘和后半程真实局面上轮换双方。每次在计时外克隆输入，单次计时只包括 `Ai.Choose`；AI 内部的复制、模拟及分配仍计入。该指标测行动选择；完整对局吞吐只覆盖普通难度的补位，不能用来说明专家补位的单步延迟。
- T-108 保留 `ai.expert` 的三局面、双方轮换和原样本数，调用的仍是默认 `Ai.Choose(..., Expert)`。新增 `ai.expert.default_budget` 与 `ai.expert.unlimited` 使用相同三个局面，并加入明确标注的构造复杂局面；仅计时 `Ai.ChooseExpert`。两者的工作量不同于旧三局面指标，不能直接用追加指标与旧 `ai.expert` 比均值。
- `Battle.Clone()` 和 `StateHash()` 使用带真实日志及回放历史的中盘局面。报告记录快照回合、日志数、事件数和状态哈希，便于确认测的是相同工作量。
- 内容加载逐一测量内置包的 `ContentDb.FromJson`，包括 JSON 解析、规则与包合并、引用校验。文本在计时外预读，**不包含磁盘 I/O 或冷缓存启动**。
- 平均值为全部计时样本的算术均值；P95 为升序排列后第 `ceil(0.95 × 样本数)` 项；最大值不剔除异常样本。快速模式中的 P95 样本较少，调查退化时应复跑完整模式。
- JSON 的 `ElapsedSecondsIncludingWarmup` 包含基准准备及预热，不包含 `dotnet` 启动/构建与最终报告写入。验收的一分钟另外用外部墙钟测量整条命令。

## 专家预算与可复现报告

专家默认预算为 **128 节点**（`ExpertBudget.DefaultMaxNodes`），无限预算对照为 `ExpertBudget.Unlimited`（`int.MaxValue`）。每次真正执行的模拟 `ResolveTurn` 或 `Replace` 在调用前扣 1 节点；克隆、评分和 Hard 启发式不计节点。取得不到下一节点即停止，未完成补位的候选不参与完整候选评分。`BudgetExhausted` 只表示仍需下一次转换但预算不足；恰好用完且搜索已经完成时为 false。节点预算不读取时间，200 ms 是本机计时目标而非跨机器的时间保证。

JSON 在保持现有字段含义的基础上追加 `Benchmark.Expert`：保存默认/无限预算值、节点定义、构造方式、四个输入快照和逐局面/双方结果。每个 `Cases` 项包含动作类型与零基索引、`SimulatedNodes`、`BudgetExhausted`、决策后状态哈希及该项的均值/P95/最大耗时。决策后哈希包括真实 RNG 状态，可区别平分时的随机数消耗。每个计时样本都从同一快照克隆，所有非计时结果必须与预热相同，否则工具报错；显式默认预算还与普通专家入口核对动作和哈希。

追加指标对每个预算、局面、方号各预热 1 次，快速/完整模式分别采样 4/40 次，每个预算合计 32/320 个计时样本。另以 8 节点对四局面双方各重复 2 次，输出到 `Diagnostics`（`Timing=null`），验证截断结果的合法性与确定性；这部分不计时，也不替代默认预算的性能指标。每次选择均检查节点数不超过预算。

复杂局面是压力构造，**不作为合法对局录像**：从同一开局克隆，保留 Choose 阶段、12 人阵容、技能和 PP；每名主播的人气与五项等级按固定槽位公式设置，双方场上各有 3 个弱化状态、7 个直播间效果，包括持续伤害、回复、减伤、蓄力、印记和反弹。完整公式、剩余回合和层数写入 `ComplexConstruction`，不改内容库或其他三份真实快照。它用于扩大候选与结算负担，不能据此推断实战胜率；强度对照由 `Tools/Ladder` 单独评估。
